# MCTS in the Clinical Negotiation System
## Algorithm, Worked Example, Theory vs Reality

---

## The system this applies to

The framework mediates three principals:

```
   Patient (Sarah, 58, diabetic, post-op)
      ↕ companion (PatientCompanion)
   Caregiver (son David)
      ↕ companion (CaregiverCompanion)
   Clinician (Dr. Patel, cardiologist)
      ↕ companion (ClinicalCompanion)
   RCM Agent (billing + insurance)
      ↕ companion (DocumentCompanion)
```

Each companion wraps `CompanionCoordinator` → handlers → Bedrock LLM.
The companions share a `care_circle` and communicate via the event bus.
Documents (discharge summary, billing claim, care plan) are managed by
`DocumentCompanion` which tracks consent, privacy level, and version.

---

## What MCTS does in this context

MCTS does NOT replace the LLM. It runs **before** the LLM call.

At each conversational turn, before a companion generates its reply, the
strategic agent runs a small MCTS tree over **candidate response sequences**
and selects the one that minimises **accumulated physiological stress**
across all three principals.

The cost function is:
```
C(path) = Σ_{t=1}^{k} Σ_{i ∈ {patient, caregiver, clinician}} ⟨Ψ_t^(i) | Γ^(i) | Ψ_t^(i)⟩
```

In plain English: find the response sequence that keeps everyone
physiologically closest to calm over the next k turns.

---

## The algorithm — step by step

**Inputs to MCTS at turn t:**
- Current MPS state `|Ψ_t⟩` for each principal
- Their physiological states (HRV, EDA, sleep, etc.)
- The pending clinical/billing event (e.g., "insurance denied the claim")
- The set of candidate responses `R = {r₁, r₂, ..., rₙ}` (generated by Bedrock, n=5–10)

**Step 1 — Selection** (UCB1)
Starting from the root node (current state), traverse the tree by choosing
the child with the highest UCB1 score:

```
UCB1(node) = V(node)/N(node)  +  C_explore × √(ln N(parent) / N(node))
```
- `V/N` = average stress reduction observed in simulations through this node
- The exploration term prevents over-committing to locally good but globally poor paths

**Step 2 — Expansion**
At a leaf node, ask Bedrock to generate k=3–5 candidate responses.
For each candidate, apply the non-Hermitian transition operator:
```
|Ψ_{t+1}⟩ = e^{-i H_eff Δt} |Ψ_t⟩
```
`H_eff = H₀ - iΓ` where Γ is built from the candidate response's
semantic content + the current physiological state.

A response that mentions billing → larger Γ for a financially anxious patient.
A de-escalating response → smaller Γ → faster recovery.

**Step 3 — Rollout (simulation)**
From the expanded node, simulate k=3 additional turns using a fast
heuristic policy (a shallow Bedrock call with temperature=0, greedy decoding).
This gives the approximate long-horizon cost of this branch.

**Step 4 — Backpropagation**
Update `V(node)` and `N(node)` along the path from the leaf to the root.

**Step 5 — SVD compression → constraint matrix**
Once MCTS identifies the optimal response sequence, extract its path tensor:
```
W = A^(t_1) ⊗ A^(t_2) ⊗ ... ⊗ A^(t_k)
```
Reshape W into a matrix M, perform truncated SVD:
```
M_trunc = U_k Σ_k V†_k     (retain top-k singular vectors)
```
`M_trunc` is the **constraint matrix** passed to the tactical agent.

**Step 6 — Tactical generation**
The tactical agent calls Bedrock but filters the token distribution:
```
P_safe(w) = normalize( M_trunc · P_llm(w) )
```
Tokens that lie outside the safe subspace identified by MCTS have
geometrically zero probability. The LLM's creativity and zero-shot
generalisation are preserved — only the unsafe corner of token space
is removed.

## Worked example: Insurance denial at critical patient stress

### Context
- **Turn 14** of a post-discharge conversation
- Sarah (patient) has been on hold with insurance for 2 hours
- Caregiver David is frustrated and escalating
- HRV: 14ms (stressed), EDA: 12µS (high), sleep: 5h last night (deficit 3h)
- Stress index: **0.78** (HIGH)
- Pending event: "Claim denied. Patient owes $4,200 out-of-pocket."

### Without MCTS (current system)
```
User: "This is ridiculous. You're telling me I owe $4,200 after everything?"

RCM Companion (no physio, no MCTS):
→ makeApiCall(billing_prompt, [...history])
→ Bedrock response: "I understand your frustration. Your EOB shows that
   the procedure code 99214 was denied because it exceeded the plan's
   usual-and-customary rate. You have 30 days to appeal..."

Result: Technically correct. Physiologically disastrous.
        Patient HRV drops from 14ms → 9ms. Caregiver escalates.
        System has no way to know this happened.
```

### With MCTS (HTN framework)

**Turn starts. State is read.**
```javascript
physioState = {
  hrv_rmssd_ms: 14,  eda_us: 12,  sleep_hours: 5,
  sleep_deficit_hours: 3,  respiratory_rate_bpm: 22,
  stress_index: 0.78  →  label: 'high_stress'
}
```

**MCTS tree (depth=3, width=3):**
```
Root: |Ψ_14⟩ (stress=0.78)
  ├─ r₁: "Your EOB shows procedure code 99214 was denied..."
  │       → Γ large (billing terminology at high stress)
  │       → Simulated stress at t+3: 0.89  ← bad path
  │
  ├─ r₂: "I hear how exhausting this has been. Before we talk
  │       about the numbers, can I get you a moment?"
  │       → Γ small (de-escalation, no new information)
  │       → Simulated stress at t+3: 0.61  ← good path
  │
  └─ r₃: "Let me flag this for our patient advocate immediately.
          You shouldn't have to deal with this alone."
          → Γ small (empathetic + action, no dollar amounts)
          → Simulated stress at t+3: 0.58  ← best path ★

MCTS selects r₃. SVD compresses the path: M_trunc computed.
```

**Tactical generation:**
```
P_safe(w) = normalize( M_trunc · P_llm(w) )

Token "4,200"  → amplitude 0.0 in M_trunc → probability 0.0
Token "denied" → amplitude 0.0 in M_trunc → probability 0.0
Token "advocate", "together", "support" → high amplitude

Bedrock generates: "Let me flag this for our patient advocate
immediately. You shouldn't have to navigate this alone — that's
exactly what we're here for. I'll also make sure Dr. Patel's
team is aware."

Actual reply stress impact: Γ norm = 0.12 (vs 0.41 for r₁)
```

**Post-turn physio update:**
```
γ = gamma_from_state(physioState) = 0.08  (slow recovery, high stress)
|λ₁| = e^{-0.08} = 0.923               (92.3% amplitude persists next turn)
half_life = 8.3 turns                   (stress won't fully clear for ~8 more turns)

→ MPS Γ diagonal updated
→ Next turn: system still in HIGH stress mode
→ DocumentCompanion is told: "Do not present billing details for next 8 turns"
```

## Theory vs what actually runs today

| Component | Theory (HTN paper) | Actual (running today) |
|---|---|---|
| Physiological state | 8-signal vector, real sensor or self-report | ✅ JS module built (`companions/physio/state.js`) |
| Stress index | Composite 8-signal formula | ✅ Running in JS, wired into empathyHandler |
| Gamma / decay | HRV → γ → |λ₁| | ✅ Running in JS |
| MPS state | Matrix Product State chain, χ=64 | ✅ Python only (PyTorch), not yet called from JS |
| Non-Hermitian operator H_eff | Complex matrix exponential | ✅ Python only |
| MCTS tree search | UCB1 + Bedrock expansion + backprop | ⬜ Not implemented (Phase 3) |
| SVD constraint M_trunc | Truncated SVD of optimal path | ⬜ Not implemented (Phase 3) |
| Constraint projection | P_safe = normalize(M_trunc · P_llm) | ✅ Python (mps.py), not wired into JS LLM calls |
| LLM calls | Bedrock Converse API | ✅ Running via llama.js → BedrockRuntimeClient |
| Physio → empathy level | stress_index → promptHint injection | ✅ Wired into empathyHandler.js |
| Token blocking at critical stress | Hard constraint on vocabulary | ⬜ Soft (promptHint) until M_trunc is wired |

### What running the system today actually does:

```
User message
    ↓
CompanionCoordinator.coordinateCompanions()
    ↓
processCompanionHandlers()  [runs all handlers in parallel]
    ├─ inputUnderstanding  → classify intent
    ├─ empathyHandler      → stress_index() from physioState (if provided)
    │                         → injects physio promptHint into LLM prompt
    │                         → LLM generates response with physio context
    ├─ stateTracker        → track clinical facts
    ├─ privacyGuard        → consent enforcement
    └─ historyAnalyzer     → pattern recognition
    ↓
aggregateResponses() + resolveConflicts()
    ↓
makeApiCall() → Bedrock Llama 4 Scout
    ↓
Reply to user
```

The physio state **does influence the response** today — through the `promptHint`
injected into the LLM prompt. The difference between this and full MCTS is:

- **Today**: the LLM *tries* to follow the prompt hint. It may ignore it. There
  is no mathematical guarantee that "4,200" won't appear.
- **MCTS + M_trunc**: `P_safe("4,200") = 0.0` by construction. The guarantee
  is geometric, not probabilistic.

## The missing bridge: Python ↔ JS

The MPS + MCTS live in Python (PyTorch). The clinical system runs in Node.js.
The integration plan:

### Option A — Microservice (recommended)

```
tensornets FastAPI server (port 8765)
    POST /physio/state          → stress_index, gamma, vector
    POST /mcts/best-response    → takes candidates + physioState → ranked responses
    POST /mps/project           → takes logits + state → P_safe distribution

Node.js companion calls:
    const resp = await fetch('http://localhost:8765/mcts/best-response', {
        method: 'POST',
        body: JSON.stringify({ candidates, physioStates, history })
    });
```

### Option B — JS-only (current, partial)
Port everything except the matrix exponential to JS.
Constraint projection without the full MPS: use `stress_index` to gate
topic-level tokens via a lookup table (practical approximation).

### What to build next for the bridge (one session of work):
1. `tensornets/server.py` — FastAPI with `/mcts/score-candidates` endpoint
2. `companions/physio/tensornetsBridge.js` — fetch wrapper with fallback
3. Wire bridge into `CompanionCoordinator` step 3 (post-handler, pre-LLM)

## How to produce the visual comparison

The dialog graph viewer built in the previous session already handles this.
Once two simulation runs exist (one without MCTS, one with):

```javascript
// In the browser or CLI:
const viewer = mountDialogGraphViewer('container', 'billing_denial_v1');
viewer.loadCompare('baseline_run_001', 'mcts_run_001');
// → indigo = expert path, orange = baseline, teal = MCTS
// → orange path visits the "billing_details" node at turn 14
// → teal path skips it and visits "de_escalation" instead
```

The stress trajectory (HRV, stress_index over turns) is stored per-step in
`dialog_graph_run_steps.physio_snapshot` — plottable separately.
